## 1. 项目背景与意义

### 1.1 社会背景

随着我国经济社会发展和人民生活水平提高，健康养生已成为全民关注的热点话题。国家卫健委数据显示，我国慢性病患者已超过 3 亿人，慢性病导致的死亡占总死亡的 88.5%。与此同时，人口老龄化加速，60 岁以上老年人口已突破 2.8 亿。

在"健康中国 2030"战略指引下，**预防为主、中西医并重**成为健康事业发展的重要方向。传统中医养生理念强调"治未病"，与现代健康管理理念高度契合。

### 1.2 政策背景

- 《"健康中国 2030"规划纲要》明确提出"坚持预防为主，中西医并重"
- 《中医药发展战略规划纲要》推动中医药与互联网深度融合
- 鸿蒙操作系统的推出为国产移动应用生态带来新机遇

### 1.3 项目意义

**茹安阁**项目旨在借助 HarmonyOS 生态与人工智能技术，将传统中医养生智慧与现代健康管理方法相结合，打造一款人人可用的智能健康养生平台，让优质的养生健康服务触手可及。

## 2. 市场分析与用户痛点

### 2.1 目标用户群体

| 用户群体 | 特征 | 核心需求 |
|----------|------|----------|
| 中老年人群 | 关注养生、慢性病管理 | 简单易用、健康监测、亲情关怀 |
| 职场青年 | 亚健康、压力大 | 便捷记录、AI 建议、效率工具 |
| 慢病人群 | 高血压、糖尿病等 | 数据追踪、医生咨询、饮食指导 |
| 中医爱好者 | 信赖中医、注重调理 | 舌诊分析、体质辨识、养生方案 |

### 2.2 用户痛点分析

| 痛点 | 说明 |
|------|------|
| **健康数据分散** | 血压、血糖、体重等数据散落在不同 App，无法统一管理 |
| **养生知识难辨真伪** | 网络养生信息鱼龙混杂，普通人难以判断科学性 |
| **就医不便** | 小毛病跑医院费时费力，线上问诊缺乏健康数据支撑 |
| **家人健康难关注** | 子女在外工作，无法及时了解父母健康状况 |
| **中医舌诊门槛高** | 传统舌诊需要专业中医师，普通人无法自我评估 |

### 2.3 竞品分析

| 竞品 | 优势 | 不足 |
|------|------|------|
| 某健康 App | 用户基数大、功能全面 | 偏西医指标，中医养生弱 |
| 某中医 App | 中医内容专业 | 互动性差、缺少智能分析 |
| 某问诊平台 | 医生资源丰富 | 缺乏健康管理闭环 |

**茹安阁的差异化：** 中医养生 + AI 智能 + 健康管理 + 亲人关怀，四位一体的完整闭环。

### 4.2 核心功能详解

#### 4.2.1 健康卡与结构化指标

**功能描述：**
- 统一管理 10+ 种健康指标：血压、血糖、心率、睡眠、体重、BMI、体温、血氧、步数、水分
- 每种指标支持结构化录入（如血压的收缩压/舒张压/脉率）
- 自动根据中国成年人标准评估正常/关注/紧急三级
- 生成健康卡摘要，一目了然掌握健康状态

**技术实现：**
- 统一数据表结构 + JSON 扩展字段，灵活支持多类型指标
- 内置参考范围与评估逻辑，保存时自动计算
- 趋势图表可视化，支持日/周/月视图

#### 4.2.2 AI 舌象分析

**功能描述：**
- 用户拍摄或上传舌象照片
- AI 自动识别舌质颜色、舌苔厚薄、舌形等特征
- 基于中医舌诊理论给出健康参考与调理建议
- 历史舌象对比，跟踪健康变化

**技术实现：**
- 后端异步任务处理，用户可随时查看进度
- 质量检查机制，确保照片符合分析要求
- 分析结果结构化存储，便于对比与追踪

#### 4.2.3 AI 养生助手

**功能描述：**
- 智能对话问答，解答健康养生问题
- 场景化建议：基于天气、季节、节气、体质
- 每日养生建议：饮食、运动、作息全方位
- RAG 知识库支撑，回答专业可靠

**技术实现：**
- RAG 检索增强生成 + 大语言模型
- 中医养生知识库：食疗、穴位、起居、情志
- 对话上下文记忆，多轮交互自然流畅

#### 4.2.4 在线问诊系统

**功能描述：**
- 医生列表展示，按科室/评分/价格筛选
- 图文问诊：文字、图片、健康快照
- 健康快照：一键发送健康卡 + 舌象照片
- 评价体系：评分 + 文字评价

**技术实现：**
- 医生资质审核机制
- 实时消息通知
- 问诊状态机管理（待接诊/进行中/已结束/已取消）

#### 4.2.5 亲人关怀

**功能描述：**
- 手机号邀请亲人加入
- 健康数据授权共享（按指标类别细粒度控制）
- 子女端查看父母健康卡与异常提醒
- 7 天/30 天历史窗口配置

**技术实现：**
- 双向关系模型，邀请/接受/拒绝流程
- 细粒度授权：支持按指标类别单独授权
- 权限中间件严格校验，保护隐私安全

### 5.5 关键技术方案

#### 5.5.1 结构化健康指标建模

采用"**统一表 + JSON 扩展**"的设计模式：

```
structured_health_measurement
├── id (主键)
├── user_id (用户ID)
├── metric_code (指标编码：BLOOD_PRESSURE / BLOOD_SUGAR / ...)
├── measured_at (测量时间)
├── type_specific_json (类型专属数据，JSON格式)
├── assessment_result (评估结果：NORMAL/CAUTION/URGENT)
├── assessment_detail (评估详情)
└── ...
```

**优势：**
- 新增指标类型无需修改表结构
- 查询列表统一接口，简化前端开发
- 评估逻辑统一封装，一致性有保障

#### 5.5.2 异步 AI 任务处理

舌象分析、建议生成等耗时操作采用异步任务模式：

1. 用户发起请求 → 创建任务记录（状态：GENERATING）
2. 后台线程/服务处理任务 → 更新进度
3. 用户轮询/推送获取进度 → 完成后获取结果
4. 失败支持重试（有最大重试次数限制）

#### 5.5.3 亲人授权与隐私保护

```
family_relation
├── inviter_id (邀请人)
├── invitee_id (被邀请人)
├── status (状态：待确认/已激活/已拒绝/已解除)
├── inviter_granted_categories (邀请人授权的指标类别，JSON数组)
├── invitee_granted_categories (被邀请人授权的指标类别)
├── history_window_days (历史数据可见天数)
└── ...
```

- **双向授权**：双方独立控制授权范围
- **细粒度**：按指标类别（血压/血糖/心率/睡眠等）单独授权
- **时间窗口**：可配置仅分享最近 7 天/30 天数据
