1. 项目概述

养生助手是一款基于 HarmonyOS 开发的智能健康管理应用，定位为"本地记录驱动的日常养生助手"。项目涵盖三端完整实现：HarmonyOS 前端 App、Spring Boot 主后端、Node.js AI 编排后端，融合了中医体质问卷、天气养生建议、AI 智能问答、RAG 知识检索、在线问诊、积分商城等功能。

核心定位
以用户健康档案为中心，结合天气环境、体质倾向和中医知识库，通过 AI 提供个性化的养生建议。支持用户、医生、管理员三种角色，实现问诊、健康管理和运营管理闭环。

1.1 核心功能

功能模块说明
AI 养生助手基于 DeepSeek / 本地 LLM，结合天气、体质、健康档案生成个性化建议，支持多轮对话
RAG 知识检索基于 MySQL 关键词检索 + Milvus 向量检索（预留），从中医知识库提取相关知识增强 AI 回复
中医体质问卷标准化问卷评分，判定九种体质倾向（平和质、气虚质、阳虚质等），提供体质专属建议
天气养生联动实时获取定位天气，根据温湿度、天气状况生成养生提醒（湿热、干燥、风寒等）
舌象记录用户记录舌质颜色、舌苔、干燥度等，作为 AI 问答的上下文
健康指标管理记录血压、血糖、心率等指标，支持趋势分析和状态判断
在线问诊用户向医生发起问诊，支持图文消息交流，医生可查看用户健康档案
积分商城每日签到、AI 问答消耗积分、商品兑换、订单管理
角色化界面用户端（首页/助手/问诊/档案/我的）、医生端（工作台/问诊/助手/资料/我的）、管理员端（总览/人员/问答/问诊/我的）
系统提醒基于 HarmonyOS reminderAgentManager 和 notificationManager 实现本地健康提醒
管理员后台用户管理、医生管理、问答日志、问诊管理、商品管理等

2.2 调用链路

App → Spring Boot → Node.js AI → LLM

App 发起 HTTP 请求到 Spring Boot（8181），Spring Boot 处理认证后，将 AI 相关请求转发到 Node.js（8787），Node.js 通过 LangGraph 工作流编排后调用 DeepSeek LLM 生成回复，结果原路返回。若 LLM 不可用，Node.js 规则引擎兜底回复。

同时 Spring Boot 自身也实现了 RAG 检索（KnowledgeRetrievalService）和 AI 客户端（OpenAiCompatibleHealthQuestionAiClient），可以直接调用 DeepSeek API。Node.js 后端作为可选的 AI 编排层，提供更复杂的工作流能力。

6.3 LangGraph 工作流

这是 Node.js 后端的核心，通过 @langchain/langgraph 构建健康助手状态机：

START → buildMemoryContext → detectRisk
                         ├── [riskLevel=urgent] → buildSafetyReply → normalizeReply → buildPlan → attachPlan → END
                         └── [riskLevel=normal] → generateReply  → normalizeReply → buildPlan → attachPlan → END
节点功能
buildMemoryContext从 profile 和 history 构建记忆上下文（体质 + 舌象 + 指标 + 最近对话）
detectRisk关键词检测风险信号（胸痛/呼吸困难/晕倒/剧烈头痛等），返回 urgent 或 normal
buildSafetyReply风险为 urgent 时直接返回规则兜底回复，不调用 LLM
generateReply风险为 normal 时调用 LLM 生成回复（可注入自定义 LLM 函数）
normalizeReply标准化回复结构，添加 workflow: 'langgraph' 标记
buildPlan根据回复生成三时段养生计划（morning/afternoon/evening）
attachPlan将 plan 合并到最终回复
安全设计
风险等级为 urgent 时，直接走规则兜底回复，绕过 LLM，确保紧急风险信号不会由 AI 生成可能不安全的建议。

6.4 LLM 集成

配置解析（llmConfig.js）按优先级解析：

  • DEEPSEEK_API_KEY / LOCAL_LLM_API_KEY / LLM_API_KEY → apiKey
  • LOCAL_LLM_BASE_URL → 本地 OpenAI 兼容服务（如 Ollama）
  • 无配置时 → 走规则引擎兜底

提示词构建（buildLlmPrompt）组合以下信息：

  1. 系统提示（中医养生助手 + JSON 格式要求）
  2. 用户体质倾向
  3. 健康档案摘要（舌象/健康指标/提醒设置）
  4. 最近对话历史（最多 6 条）
  5. 当前天气信息（温度/湿度/天气风险）
  6. 用户当前问题

6.5 规则引擎

当 LLM 不可用时，ruleAssistant.js 通过关键词匹配生成养生建议，覆盖 6 类场景：

场景关键词建议方向
紧急风险胸痛/呼吸困难/晕倒/剧烈头痛/半身麻木/说话不清及时就医，停止自行调理
睡眠失眠/睡不着/熬夜睡前放松，减少咖啡因，固定入睡时间
饮食饮食/胃口/清淡/脾胃/消化规律三餐，少冰冷，清淡饮食
乏累疲劳/困/没精神/气虚循序渐进运动，午间小憩
运动运动/锻炼/久坐/步数温和运动，久坐拉伸，饭后散步
默认-规律作息，清淡饮食，温和运动

8. AI / RAG 实现机制

8.1 AI 对话完整链路

用户提问
  ↓
AssistantController.chat()
  ↓
AiRateLimitService.tryAcquire()      // 速率限制
  ↓
RewardsService.reserveChat()          // 预留积分
  ↓
HealthQuestionService.addHealthQuestion()  // 保存待处理问题
  ↓
AssistantChatService.chat()
  ├── KnowledgeRetrievalService.retrieve()  // RAG 关键词检索
  ├── HealthQuestionPromptBuilder.build()   // 提示词构建
  └── HealthQuestionAiClient.generateAnswer()  // 调用 LLM
  ↓
HealthQuestionService.answerHealthQuestion()  // 保存答案
  ↓
RewardsService.completeChat()         // 扣除积分
  ↓
返回 AssistantChatReply              // 回复+风险+建议+计划+免责声明

8.2 RAG 检索机制

Spring Boot 后端的 RAG 实现包含两个层次：

关键词检索（已实现）

  • 服务：KnowledgeRetrievalService
  • 方式：使用 JdbcTemplate 直接查询 MySQL
  • 分词：对 queryText 按逗号/分号/换行分割，取前 8 个词
  • 匹配：对每个词执行 LIKE 查询 medical_knowledge_chunk 表的 title、content、keywords 字段
  • 排序：按 risk_level 降序（EMERGENCY > HIGH > MEDIUM > LOW）
  • 数量：默认 top-k=6

向量检索（预留）

  • 接口：MilvusVectorClient
  • 当前实现：NoopMilvusVectorClient（返回空列表）
  • 配置：Embedding 模型 bge-m3，Milvus 集合名 medical_knowledge
  • 用途：未来接入 Milvus 向量数据库实现语义检索

RAG 建议生成

RagSuggestionService 合并关键词命中和向量命中结果后：

  1. 使用 RagSuggestionPromptBuilder 构建提示词
  2. 调用 LocalLlmClient.generate() 生成 JSON 格式建议
  3. 解析为 LocalLlmSuggestionResult（summary、suggestions、plans、riskLevel、scenario、disclaimer）
  4. 通过 RagRetrievalLogService 记录检索结果

8.3 AI 客户端

OpenAiCompatibleHealthQuestionAiClient 使用 Java HttpClient 发送 POST 请求：

  • 端点：/chat/completions
  • 格式：application/json
  • 参数：model、messages、temperature、max_tokens
  • 支持 DeepSeek API 和任何 OpenAI 兼容 API

8.4 提示词构建

AI 对话的 system message 包含：

  1. 角色定位（中医养生助手）
  2. 用户体质倾向
  3. 健康档案摘要（舌象/健康指标/提醒设置）
  4. RAG 检索到的相关知识片段
  5. 当前天气信息
  6. 最近对话历史（最多 memoryWindow × 2 条，每条截取 4000 字符）
  7. JSON 格式输出要求

9.1 Token 认证

  • 6 位数字随机验证码

  • 存储：内存 ConcurrentHashMap

9.5 前端会话管理

HarmonyOS 前端通过 AuthService 管理会话：

  • 登录/注册成功后保存 AuthSession 到 preferences（storeName: wellness_auth）
  • 运行时维护 runtimeAuthToken 变量
  • 后续请求通过 buildAuthorizedJsonHeaders() 自动添加 Authorization 头
  • 遇到 401 时触发 SessionInvalidationService 全局回调，清除登录状态返回登录页

11. 核心业务流程

11.1 用户登录流程

1
输入手机号和密码

用户在 AuthView 输入手机号（11位）和密码（6-64位），或选择验证码登录

2
前端校验

AuthService.isValidPhone() 和 isValidPassword() 校验格式

3
发送请求

POST /api/auth/login，请求体包含 phone 和 password

4
后端验证

Spring Boot AuthController.login() → UserService 查询用户 → BCrypt 密码比对 → 生成 Token

5
返回会话

返回 {token, user: {id, phone, roles, primaryRole}}

6
前端保存

AuthService 保存 session 到 preferences，设置 runtimeAuthToken

7
角色路由

RoleExperienceService 解析主角色，生成对应 Tab 列表，进入主界面

11.2 AI 对话流程

1
用户输入问题

在 AssistantTab 输入养生问题，前端构建请求体（message, requestId, profile, weather, history）

2
发送请求

POST /api/ai/chat，携带 Authorization 头

3
后端处理

拦截器验证 Token → AiRateLimitService 限流 → RewardsService.reserveChat() 预留积分

4
RAG 检索

KnowledgeRetrievalService.retrieve() 从 MySQL 关键词检索相关知识片段

5
提示词构建

HealthQuestionPromptBuilder 组合体质、档案、天气、RAG 知识、历史对话为 system message

6
调用 LLM

OpenAiCompatibleHealthQuestionAiClient 调用 DeepSeek API 生成回复

7
保存与扣费

保存问答记录 → RewardsService.completeChat() 扣除积分 → 返回回复

8
前端展示

解析回复（回答 + 建议 + 计划 + 风险等级 + 免责声明）并渲染到聊天界面

11.3 体质问卷流程

1
入口

首页快捷入口"体质问卷" → QuickActionView 渲染 QuestionnaireFlow

2
答题

用户依次回答问卷题目，每题有选项和分值

3
评分

QuestionnaireService 计算总分，判定体质类型（平和质/气虚质/阳虚质等）

4
保存

ProfileRepository.saveQuestionnaireRecord() → 本地 preferences + POST /api/health-detail/questionnaire

5
应用

体质结果用于后续 AI 对话的上下文，影响建议方向

11.4 在线问诊流程

1
用户发起问诊

POST /api/consultation，填写标题、症状、描述

2
医生查看

医生在"问诊"Tab 查看待处理问诊列表，点击进入详情

3
消息交互

POST /api/consultation-message 发送消息，GET /api/consultation-message/list 获取消息列表

4
查看档案

医生可查看用户的健康档案（体质、指标、舌象），辅助诊断

5
结束问诊

PUT /api/consultation/status 更新问诊状态为已完成

11.5 天气养生联动

1
获取定位

WeatherService.requestLocationPermission() → requestCurrentCoordinate()

2
请求天气

GET /api/weather/current?latitude=...&longitude=...，支持多候选地址重试

3
后端代理

Spring Boot WeatherController → OpenMeteoWeatherProviderClient → Open-Meteo API

4
养生关联

湿度 ≥ 75% → 湿热提醒；湿度 ≤ 35% → 干燥提醒；生成天气养生建议

5
前端展示

首页展示天气卡片，同时天气数据作为 AI 对话和建议请求的上下文
